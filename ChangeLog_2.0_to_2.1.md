# Changelog

## 2.1

Changes from version 2.0 (commit `a6c414b` "Version 2.0", 2026-10-14).

### Version

- The app is versioned as **2.1** (`package.json` / `package-lock.json` 2.1.0).
- The version shows next to the title in the left panel and in the User Guide.

### Label text - always the component's value

- A label of a component shows **only the values of the attributes it references** on that component, never the literal `<Data property="Text">` string stored in the file. When the referenced attribute has no value, nothing is shown (e.g. a line label referencing `ObjectDisplayName` on a `PipingNetworkSegment` that has none).
- An attribute is read only from the object the label names for it, and only when the attribute is valid for that object's class in the loaded profile. No search through nested or connected objects any more (a segment's line label used to pick up the nozzle tag `N05` through the segment's `TargetItem`).
- A label may reference, besides the labelled component itself: its plant structure items (`PlantSystem`, `ParentStructure` chain, e.g. `ProcessPlantIdentificationCode` / `PlantSystemIdentificationCode`), a connected object named by a role path in the template (`SignalConveyingFunction:<AlarmValue>`), an off-page connector's `ConnectorReference` object (`PipeOffPageConnectorReferenceByNumber` / `SignalOffPageConnectorReferenceByNumber` carrying `ReferencedDrawingNumber` / `ReferencedDrawingDescriptor`), or a `Core/Note`. Any other reference shows nothing.
- All DEXPI label types are recognised (`Core/Diagram.Label` and the `Plant/Diagram.*Label` subtypes such as `SafetyValveOrFittingLabel`), so e.g. the DEXPI reference P&ID's safety valve label shows `P = 6 barg` from `SetPressureHigh` instead of the stored `P = 16 barg`.
- **Units** are shown with their symbol from `Core.xml` (`src/unitSymbols.js`, generated by `scripts/genUnitSymbols.py`); gauge pressure units get a `g` (`PressureGaugeUnit.Bar` → `barg`).
- **Profile loaded** (DiscProfile.xml):
  - a label is shown only when its component is placed with a profile symbol that defines label templates, or when it is linked to a `Core/Note` and references a valid Note attribute (`NoteText`, `LocalNoteIdentifier`); a Note label may contain literal text;
  - a literal in a label is shown only when it matches a literal of the profile label template for that symbol (`P = `, `-`, `EL: `, `HH=`); other literals are hidden;
  - a label with no attribute reference shows nothing.
- **No profile loaded**: a label with attribute references shows the component values and its literals; a label with no attribute reference shows its stored text.
- Alarm rows (`HH=` / `H=` / `L=` / `LL=`) show the literal as soon as the matching `SignalConveyingFunction` (by `PortStatus`) exists, and the value with its unit once it has an `AlarmValue`.

### Only graphics that belong to a model object are drawn

- Every drawn element (symbol, label text, line, connector line) must sit in a group that represents an existing model object. Bare graphics exported without a component behind them - SPPID's `DrawingLabels` polylines (frames, table lines, interface markers), free text not turned into a `Core/Note` - and anything whose `Represents` target does not exist in the file are not drawn.
- With a profile loaded, a bare polyline or polygon is drawn only when it is a piping or signal line drawn without a symbol, or an open line (a leader) in a group that has a profile symbol. A closed shape next to a symbol duplicates the symbol's own graphics (SPPID exports its slope triangle beside the ND0224 symbol usage and its flow arrow beside ND0010) and is not drawn; nor are frames, tables or package boundaries drawn without a symbol.
- `scripts/Convert-DexpiTextToNotes.ps1` (new) turns the free text of the `DrawingLabels` group into `Core/Note` components (NoteText = the text as shown, `LocalNoteIdentifier` from `NOTE n` flags), each in its own RepresentationGroup that represents the Note, so notes, note flags and title block texts stay visible. Texts in labels holding graphics (revision table, change-flag table) are skipped and reported.

### Profile labels - placement under rotation and mirroring

- A profile label template is defined for the symbol at rotation 0, not mirrored. On the drawing the text is always kept readable (left to right, or bottom to top beside a vertical symbol), and never turned upside down or right to left.
- Per axis of the symbol: where the symbol extends to both sides of its origin the label keeps its side (an off-page connector at 180° still has its descriptor above and its drawing number in the box); where the symbol lies on one side of its origin the label follows the symbol (a shutdown symbol at 180° keeps its tag inside the rectangle). Mirroring and scaling act on the label like on the symbol.
- Left/Right and Top/Bottom are chosen so the text grows away from the symbol, as the template intends. This matches where drafters placed their own labels on rotated and mirrored symbols in the SPPID exports.
- Mirrored symbols were not handled before (Left/Right was not swapped). Labels stored in the file are drawn exactly as written: position, rotation and alignment.

### Label update script - `scripts/Update-DexpiLabels.ps1` (new)

PowerShell script that brings exported DEXPI 2.0 files in line with the DISC profile labels, writing copies to `<folder>\LabelUpdated` plus `LabelReport.csv`. Steps, per file:

1. **ItemTag → ObjectDisplayName** for every element whose symbol labels allow `ObjectDisplayName` and that has no label referring to it yet (aliases such as `SPPID: ItemTag`, `PipingComponentNumber` included).
2. **Remove invalid label lines**: a label line is removed when none of its attribute references is an attribute of the element's profile symbol label templates (a line in a label symbol such as ND0040 is judged against that symbol's templates); pure literal lines too. Lines referencing a Note are kept; a label left empty is removed (`-KeepInvalidLabels` skips this).
3. **Repair** label groups that reference valid attributes but on the wrong lines (e.g. ND0248B instrument labels repeating `<Sequence><TagSuffix>` on every line): each line is matched to its template row by content, then by position; lines that fit no row are removed. Existing labels are otherwise not touched and never moved (`-MoveLabelsToProfilePlacement` moves them to the profile placement).
4. **Missing labels**: an element whose labels reference none of its symbol's label-template attributes gets a new label with one text per template row, placed with the same rotation / mirroring rule as the viewer's Profile labels; a label symbol (ND0040 on a segment) whose label has no valid text gets the template texts added into it. `ProcessInstrumentationFunction` labels get `ProcessPlantIdentificationCode` / `PlantSystemIdentificationCode` through the `ParentStructure` / `PlantSystem` references; `H` / `HH` / `L` / `LL` rows are added when the matching `SignalConveyingFunction` exists (`ValueAndUnits` representation).
5. **Valve update** (`OperatedValve`, `SafetyValveOrFitting`, `CheckValve`): missing row attributes are added to existing labels that already reference a valid attribute of the row.

Copy features are opt-in and off by default: `-BackfillValues` (write values read from label text into the component), `-CorrectDisplayNames` (overwrite `ObjectDisplayName` with the drawn text). Without them the script only links labels to attributes and reports differences (`DisplayNameDiffers` / `DisplayNameConflict`).
